# ตอบรับ/ปฏิเสธคำขอและที่นั่ง

ทำต่อบน PR #6 แบบ Draft ไม่merge และใช้ COAGO Test เดิม ไม่production

เจ้าของเท่านั้นตัดสินคำขอของเที่ยวตนได้ pending→accepted/rejected ตอบรับ1คำขอ=1ที่นั่ง ใช้transaction+ล็อกtripก่อนrequestทุกwrite ป้องกันตอบรับเกินจำนวนและretryไม่หักซ้ำ การตัดสินคนละอย่างหลังตัดสินแล้วเป็น409 ไม่ย้อนสถานะโดยเงียบๆ

seats_offeredเก็บจำนวนที่เปิดทั้งหมด1–8; seats_bookedเก็บจำนวนตอบรับ0..seats_offered Public/APIที่นั่งว่าง=offered-booked คำขอpendingไม่หักที่นั่ง เที่ยวเต็มไม่แสดงในsearch/upcoming ผู้เดินทางที่ตอบรับแล้วดูรายละเอียดข้อเสนอจากsnapshotส่วนตัวได้

บันทึกsnapshotรายละเอียด/ราคา/จุดรับส่งตอนส่งคำขอแบบimmutable และversionเที่ยว Acceptanceต้องversionตรงกับตอนส่ง หากรายละเอียดเปลี่ยน ให้ยกเลิกแล้วส่งคำขอใหม่เพื่อยืนยันใหม่ จำนวนที่นั่งที่ถูกตอบรับเปลี่ยนได้โดยไม่ถือว่าแก้เงื่อนไข จึงไม่เพิ่มcontent version

เมื่อมีที่นั่งตอบรับอยู่ ห้ามแก้รายละเอียดเที่ยว/จำนวนเปิดรับ เพื่อไม่เปลี่ยนข้อตกลงที่ตอบรับแล้ว เจ้าของยังยกเลิกเที่ยวก่อนเวลาออกได้:เปลี่ยนpending/acceptedทั้งหมดเป็นcancelledพร้อมbooked=0ในtransactionเดียว ประวัติไม่ลบ

ผู้โดยสารยกเลิกpendingได้เสมอ; acceptedยกเลิกได้ก่อนเวลาออกเมื่อเที่ยวactive คืน1ที่นั่งครั้งเดียว หลังออกเดินทางแล้วacceptedยกเลิกผ่านAPIนี้ไม่ได้ Rejectedไม่แปลงเป็นcancelled; ส่งคำขอใหม่หลังrejected/cancelledได้เมื่อเที่ยวมีที่ว่างและอยู่ในอนาคต ห้ามมีpending/acceptedซ้ำสำหรับคนเดียวในเที่ยวเดียว

Snapshotคำขอเก่าก่อนฟีเจอร์นี้จะbackfillจากรายละเอียดปัจจุบัน ณmigration เพราะประวัติเดิมไม่มีsnapshot หากtrip versionไม่ตรงคำขอเก่า ยังคงต้องส่งใหม่ก่อนตอบรับ ไม่อ้างว่าbackfillเป็นรายละเอียดต้นฉบับที่ไม่เคยเก็บ

เหตุผลปฏิเสธไม่บังคับ สูงสุด300ตัวอักษร เปิดให้เฉพาะคู่คำขอที่มีสิทธิ์เห็น ไม่มีการเปิดLINEID/เบอร์โทร/ทะเบียนเต็มหรือชำระเงิน เพิ่มบัญชีลบ/โอนเจ้าของต้องจัดการที่นั่งก่อนcascadeในอนาคต ยังไม่มีAPIลบบัญชีในรอบนี้

Manualที่เจ้าของยืนยันก่อนเริ่ม: ส่งคำขอ/รายการสองฝั่ง/ยกเลิกสำเร็จ ทดสอบaccept/reject/concurrentseat allocationแยกmock,realPostgreSQL,localWorkersและremote พร้อมcleanupเฉพาะsynthetic accounts


API เพิ่ม `POST /api/ride-requests/:id/decision` JSON `{ "decision": "accept" | "reject", "reason": "" }` ต้อง session เจ้าของเที่ยว, exact Origin และ CSRF token เช่น write เดิม เหตุผลใช้เฉพาะ reject; missing/invalid inputs 400, ไม่ใช่เจ้าของ 404, stale/full/terminal conflicts 409 รายการส่วนตัวคืน `offeredTrip`, `decidedAt`, `rejectionReason` เพิ่มจาก live trip ส่วน public ไม่เปิดข้อมูลคำขอหรือ identity

วิธีทดสอบด้วยสองบัญชี: ผู้โดยสารส่งคำขอใหม่ → เจ้าของเปิดคำขอที่เข้ามา/โหลดล่าสุด → ตอบรับและยืนยัน → ผู้โดยสารโหลดล่าสุดเห็นตอบรับแล้ว → ยกเลิกก่อนเวลาออก → เจ้าของโหลดล่าสุดตรวจที่นั่งคืน ทดลองปฏิเสธกับคำขอใหม่อีกครั้ง คำขอที่เจ้าของทดสอบยกเลิกก่อนรอบนี้จะไม่ย้อนกลับเป็น pending โดยอัตโนมัติ
