# ใบขับขี่ ประกาศหารถ สถานะเดินทาง และ LINE

งานชุดนี้ต่อจาก PR17: เว็บไซต์ Workers + Hyperdrive + Neon เดิม ไม่ต้องใช้ Express/nginx/Docker/uploads บน production. LIFF และ Rich Menu ยังไม่รวมในชุดนี้.

## ลำดับใช้งาน

1. สมาชิกเข้าสู่ระบบ LINE → `/account` ส่งข้อมูลสมาชิก รอ Root/Admin อนุมัติ.
2. ผู้แชร์รถส่งใบขับขี่ (เลข ชนิด ประเทศ วันหมดอายุ รูป) และข้อมูลรถ รอผู้ดูแลอนุมัติทั้งสองอย่าง. ผู้โดยสารไม่ต้องมีใบขับขี่.
3. ประกาศเที่ยว: เลือกรถที่ผ่านตรวจ จุดรับ–ส่ง ระยะทาง/ต้นทุนและจำนวนส่วนหาร. ราคาต่อคนคงที่ตามส่วนที่เจ้าของตั้งไว้.
4. ผู้โดยสารใช้ «ประกาศหารถร่วมทาง» ระบุเส้นทาง ช่วงเวลาไม่เกิน24ชั่วโมง จำนวน1–8ที่นั่ง และงบต่อคน (ถ้าต้องการ). ต้องผ่านตรวจสมาชิก. เปิดได้สูงสุด5ประกาศต่อคน; เริ่มเดินทางในอนาคตและสิ้นสุดภายใน90วัน. แก้/ยกเลิกของตนได้. ไม่มีชื่อ เบอร์ เอกสาร หรือช่องทางติดต่อส่วนตัวในรายการสาธารณะ. ประกาศหารถไม่ใช่การจอง และไม่หักที่นั่ง. เจ้าของรถยังเลือกส่งข้อเสนอถึงประกาศหารถโดยตรงไม่ได้; ใช้ข้อมูลเส้นทางประกอบการประกาศเที่ยวได้.
5. เจ้าของเที่ยวกด «ดูสถานะการเดินทาง»: ยังไม่เริ่ม → เตรียมออกเดินทาง → ถึงจุดรับ → กำลังเดินทาง → ถึงปลายทาง → จบเที่ยว. เริ่มเปลี่ยนขั้นตอนก่อนเวลาออกไม่เกิน24ชั่วโมง. ห้ามข้าม/ย้อนขั้นตอน; แจ้งเหตุขัดข้องพร้อมรายละเอียด และแก้ไขเหตุขัดข้องก่อนเดินหน้าต่อ.
6. สมาชิกที่ได้รับตอบรับดูสถานะและประวัติได้; บุคคลอื่นดูไม่ได้. Root/Admin ดูรายการข้อความได้จากเมนูติดตามการเดินทาง กดเปิดรายละเอียด/แผนที่จุดรับ–ส่งได้. ผู้ดูแลอ่านได้ แต่ไม่รายงานแทนผู้ขับ. ไม่เก็บพิกัดปัจจุบัน/ติดตามGPS/อ้างตำแหน่งรถสด.
7. เมื่อเริ่ม «กำลังเดินทาง» จะซ่อนจากการค้นหา หยุดรับ/ตอบรับคำขอใหม่ และหยุดยกเลิกที่นั่งที่ยืนยันแล้วหรือยกเลิกเที่ยวตามขั้นตอนปกติ. ผู้ขับที่ใบขับขี่หมดอายุยังบันทึกถึงปลายทางและจบเที่ยวได้ เพื่อบันทึกเหตุการณ์จริง.

หน้าแรกแยกจำนวนรถ/เที่ยว/ที่นั่ง/คำขอpending/ประกาศหารถ และสรุปจังหวัดของประกาศหารถจากข้อมูลจริง. การระงับสมาชิกซ่อนประกาศหารถของผู้นั้นทันที ผู้ดูแลใช้เมนูจัดการผู้ใช้เดิม; ยังไม่มีเมนูลบประกาศหารถรายชิ้นโดยผู้ดูแล.

## ความปลอดภัยและข้อมูล

รูปใบขับขี่ใช้ private encrypted R2 เช่นเดียวกับเอกสารสมาชิก. เลขและข้อมูลใบขับขี่เข้ารหัสด้วย MEMBER_DATA_KEY; เก็บท้าย4ตัวและวันหมดอายุเพื่อคัดกรอง. ผู้ดูแลต้องเปิดดูเอกสารผ่าน API ที่บันทึก audit. ห้ามตรวจอนุมัติเอกสารตนเอง. ทุกการแก้ไขต้องรอตรวจใหม่; ใบขับขี่ต้องครอบคลุมวันเดินทางตามเวลาไทย. ตอนเริ่มเดินทางตรวจสมาชิก ใบขับขี่ และรถ/version ที่แนบเที่ยวอีกครั้ง.

ก่อนบันทึก/แก้ประกาศหารถตรวจการอนุญาตตำแหน่งเช่นเดียวกับประกาศเที่ยว; ไม่ส่งพิกัดปัจจุบันและไม่ถือว่า browser permission เป็นหลักฐานฝั่ง server. การอ่าน/ยกเลิกไม่บังคับตำแหน่ง.

Version locks และ request UUID ป้องกันกดซ้ำ/เขียนทับ. การปรับที่นั่งและรายงานเดินทางล็อกแถวเที่ยวเดียวกัน. API ส่วนตัวใช้เซสชัน LINE เดิมพร้อม Origin/CSRF และแยกจาก staff session; canonical-domain guard ครอบคลุม endpoint ใหม่. รายงานเหตุขัดข้องไม่ควรใส่เลขเอกสาร เบอร์โทร หรือข้อมูลอ่อนไหว.

## แจ้งเตือน LINE (ปิดเป็นค่าเริ่มต้น)

LINE Login Channel Secret ใช้แทน Messaging API token ไม่ได้. เจ้าของต้องเตรียม LINE Official Account/Messaging API ภายใต้ **Provider เดียวกัน** กับ LINE Login เพื่อใช้ user ID เดียวกัน และให้ผู้ใช้เพิ่มเพื่อน OA.

ตั้งใน GitHub Environment `production` ก่อนเลือกเปิดส่ง:

- Secret `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN`: token ของ Messaging API; ไม่ส่งในแชต.
- Variable `LINE_MESSAGING_PROVIDER_CONFIRMED=true`: เจ้าของตรวจ Provider ของทั้งสองช่องตรงกันแล้ว.
- Variable `LINE_MESSAGING_ENABLED=true`: เปิดเฉพาะเมื่อทบทวนโควตา/ค่าใช้จ่าย OA แล้ว. เว้นว่าง/false ปิดส่งและไม่ติดตั้ง Cron.

การ deploy workflow จะนำค่าลง Worker พร้อม Cron ทุก5นาทีเมื่อเปิด. ไม่เปลี่ยนแพ็กเกจหรือซื้อโควตาให้อัตโนมัติ. ถ้าต้องการปิดทันที เปลี่ยน Worker variable `LINE_MESSAGING_ENABLED=false` และตั้ง GitHub variable ให้ตรงกันเพื่อป้องกัน deploy ถัดไปเปิดกลับ.

สมาชิกเปิดยินยอมใน `/account` ได้เมื่อระบบพร้อม และปิดได้ทุกเมื่อ. คิวเฉพาะเหตุการณ์หลังยินยอม ไม่ส่งย้อนหลังทั้งหมด. แจ้งเจ้าของเมื่อมีคำขอ/ผู้ร่วมทางยกเลิก แจ้งผู้โดยสารเมื่อรับ/ปฏิเสธ/ยกเลิกเที่ยวและเมื่อรายงานเดินทาง. ข้อความมีเพียงชนิดเหตุการณ์และลิงก์เว็บไซต์ ไม่มีรูป/เอกสาร/เลขบัตร/รายละเอียดเหตุขัดข้อง. คิวสร้างใน transaction เดียวกับเหตุการณ์ ไม่เรียก LINE ภายใน transaction.

ส่งครั้งละ1งานต่อCron มีเพดานอนุรักษ์นิยม **5งาน/วัน และ50งาน/เดือนต่อระบบ** (เวลาไทย; นับงานที่เริ่มพยายามส่ง รวมงานที่ล้มเหลว). ตรวจ quota/consumption จริงก่อนส่ง; ไม่ทราบโควตาหรือเป็น unlimited จะไม่ส่ง. อย่ามองเพดานนี้เป็นหลักประกันไม่มีค่าบริการ: OA อาจมีการใช้งานจากบริการอื่นด้วย เจ้าของต้องตรวจแพ็กเกจของตน. เกินเพดานรอรอบวัน/เดือน หรือหมดอายุคิว. คิวเกิน23ชั่วโมงถูกข้าม ไม่ส่งข่าวเก่า. ไม่ส่งไปยังบัญชีระงับหรือยกเลิกความยินยอม. การปิดหลังงานถูก claim อาจหยุดข้อความที่เริ่มส่งแล้วไม่ได้.

Timeout/5xx retryสูงสุด3ครั้งด้วย retry key เดิมและเนื้อหาเดิม; 409ต้องมี accepted-request-id จึงนับว่าสำเร็จ; 4xxไม่retry. `sent` หมายถึง LINE รับคำขอ ไม่ยืนยันผู้ใช้ได้รับ/อ่าน (เช่น block OA). ไม่มี webhook/read receipt หรือการแจ้งเหตุฉุกเฉินในรุ่นนี้. ผู้ใช้ต้องตรวจรายการในเว็บด้วย.

อ้างอิง: [LINE retry](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/), [Messaging API quota/push](https://developers.line.biz/en/reference/messaging-api/).

## อัปเกรดและทดสอบ

Schema ใหม่ `0011_young_reaper` รวม **12 migrations /19 application tables**. เพิ่ม driver_licenses, wanted_posts, journeys, journey_events, notification_preferences, notification_outbox และ triggers สำหรับคิว. ไม่แก้ migrations0000–0010. การ merge ไม่ deploy หรือรันฐาน production อัตโนมัติ.

1. ทำ snapshot/ตรวจ restore ของ `coago-production` ก่อน.
2. รัน Root Admin schema workflow `check` จาก main ที่ merge ชุดนี้แล้ว ตรวจ host/name ให้เป็น production.
3. เลือก `upgrade` และยืนยัน `coago-production`; เปิด allow_existing_data เฉพาะหลังทบทวน snapshot/restore แล้ว. ตรวจผล12migrations/19tables.
4. รัน production Worker workflow แบบ `maintenance_update`; ยังไม่เปิดบริการจนทดสอบครบ. R2 private bucket/MEMBER_DATA_KEY จำเป็นสำหรับส่งเอกสาร; ORS key จำเป็นเฉพาะ routingอัตโนมัติ (manual distanceยังใช้ได้).
5. ทดสอบด้วยบัญชีสังเคราะห์สองบัญชี+staff แยก: profile/vehicle/license review, คำขอ/ตอบรับ/คืนที่นั่ง, wanted edit/cancel, รายงานสถานะ/เหตุขัดข้อง/สิทธิ์ดูแผนที่. ตรวจธีม Porcelain#FDFCF8, Onyx#111111, LimeMoss#8DB600, Mustard#FFD84D และฟอร์มมือถือ.
6. LINEปิดไว้ได้ตลอดการทดสอบหลัก. ทดสอบจริงหลังตั้งOA/โควตาและสมาชิกยินยอมเท่านั้น; development tests ใช้ mocked provider ไม่มีข้อความจริง.

Checks: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm db:generate` (ไม่ควรเกิด migration เพิ่ม), local migrateซ้ำ, `pnpm test:community:integration`, `pnpm test:members:integration`, `pnpm test:admin:upgrade` และ browser suite. ทั้งหมดใช้ฐาน disposable ที่มีชื่อ `_test`.
